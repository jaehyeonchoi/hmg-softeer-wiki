## 작업 과정에서 배운 것

### 1. 스쿼드 세션에서 느낀 점

스쿼드 세션에서 지수님, 규현님과 같은 조가 되어 각자의 프로젝트 개요와 진행 상황을 공유했다.

규현님 팀은 단기 날씨 정보를 활용해 농업 종사자들에게 도움을 주는 서비스를 개발 중이었다.

규현님은 설명을 하면서 완성된 페이지들은 물론, 기획 단계에서 조사했던 자료나 사용 중인 API처럼 굉장히 세세한 부분까지 보여주려고 하셨다. 프로젝트에 얼마나 많은 관심과 애정을 쏟고 있는지 느껴졌다. 

또, 다른 사람의 설명을 들으면서 모르거나 궁금한 게 있으면 하나도 빼놓지 않고 메모해두시는 모습이 인상적이었다. 배우려는 열정이 느껴져서, 나도 아는 것을 하나라도 더 설명해드리고 싶어질 정도였다. 자바와 스프링을 사용하는 게 이번이 처음이시라고 들었는데, 벌써 프로젝트에서 역할을 당당하게 수행하고 계셔서 참 대단하다고 생각했다. 이런 열정과 호기심이 빠른 성장 속도의 원동력이 아닐까 생각했다.

지수님 팀은 노인을 위한 공유 차량 배차 시스템을 개발하고 있었다. 

차량을 어떻게 효율적으로 배치할지가 가장 중요한 부분일 것이라 생각했는데, 역시나 알고리즘이 상당히 복잡했다. 하지만 지수님께서 설명을 정말 잘하셔서 금방 이해할 수 있었다. 그림과 예시를 통해 다양한 케이스들을 설명해주셔서, 서비스가 하고자 하는 일이 무엇인지 뚜렷하게 알 수 있었다. 

또 하나 인상적이었던 것은 문서화였다. 개발 과정에서의 인사이트나 트러블슈팅을 팀원들 모두가 볼 수 있는 공간에 문서로 남겨 공유하고 있었는데 참 좋아보였다. 팀원들이 어떤 어려움을 겪고 있는지, 말로 설명하는 것보다 더 깊고 명확하게 이해할 수 있을 것 같았다.

## 어려웠던 점

### 1. 통합테스트 관리

어제 고객 사이드 개발을 마무리하면서 오늘 데모 활동을 대비하여 통합테스트를 작성했다. 그동안 개발했던 코드를 검증하고 개선할 수 있어 좋았다.

하지만 오늘 새로운 API를 개발하면서 컨트롤러와 DTO에 변경 사항이 생겼다. 어제까지 정상적으로 통과했던 통합 테스트들 일부가 실패하기 시작했다. 이를 모두 통과하게 만들려면 서비스 레벨의 코드까지 수정해야 했는데, 이번 이슈에서 처리할 내용은 아니라고 판단하여, 일단 실패한 테스트를 주석 처리하고 머지했다.

어제까지만 해도 통합 테스트를 빨리 해봐서 참 좋다고 생각했는데, 오늘은 반대로 부작용을 느껴볼 수 있었다. 통합 테스트는 동작 여부를 빠르게 확인할 수 있다는 장점이 있지만, 새 기능을 추가할 때 기존 테스트를 함께 수정해야 하는 관리 부담이 있다는 점을 간과했다. 앞으로는 통합 테스트를 좀 더 효율적으로 유지·관리할 방법을 고민해 봐야겠다.

# 2. 회고

## Keep

### **1.** 다른 팀 사람들에게 프로젝트를 설명하기

- 스쿼드 세션 시간에 지수님, 규현님에게 우리 프로젝트와 개발 과정을 설명드렸다.
- 머릿속에 있는 내용을 다른 사람들이 금방 이해할 수 있도록 설명하는 것이 쉽지 않았다.
- 그래도 예시 케이스를 들어가며 설명하니 듣는 사람들이 쉽게 이해할 수 있었고, 관련된 추가 질문도 더 활발하게 나왔다.
- 설명 과정에서 그동안 내가 고민했던 내용들을 다시 떠올리고, 말로 풀어내면서 생각이 더 구체화되고 체계화되는 효과가 있었다.
- 앞으로도 이런 기회를 자주 만들어, 프로젝트를 외부인에게 설명하는 연습을 하고 싶다.

<br>

## Problem

### **1. PR 머지 순서**

- 통합 브랜치에 PR을 머지하는 과정에서 뒤에 올라온 PR이 먼저 병합되면서, 이전에 문제없던 PR에서 코드 충돌이나 테스트 실패가 발생했다.
- 이미 완성한 PR을 다시 수정해야 했고, 오래전에 올린 PR에서 추가 수정 사항이 생기면서 해당 작업에 오래 묶이게 됐다.
- 이 과정에서 이후에 올라온 다른 PR과도 충돌 가능성이 높아져 전체 개발 흐름이 늦어졌다.

### 2. 코드를 작성하고 고치는 데 들이는 시간이 많다

- 개발 전에 성훈님과 API나 계층 구조에 대해서 미리 이야기를 하고 있는데, 그럼에도 불구하고 리뷰를 하다보면 서로 생각이 달랐던 부분이 생긴다.
- 기능적으로는 문제가 없더라도, 서로 다른 스타일과 구조가 섞이면 유지보수성이 떨어지기 때문에, 통일된 방식으로 다시 작성하고 있다.
- 한 번에 맞춰 작성했다면 들이지 않아도 될 시간을 쓰게 된다.

<br>

## Try

### **1. PR 머지 순서 판단을 잘하자**

- PR은 가능한 한 일찍 올라온 순서대로 빠르게 리뷰하고 병합하도록 하자.
- 단순히 순서뿐 아니라, 코드 양, 변경 범위, 다른 PR과의 의존 관계까지 고려해 머지 우선순위를 정해야 한다.
- 리뷰 단계에서 코드 내용뿐 아니라 머지에 대한 순서와 전략도 함께 결정해 충돌 가능성을 줄이자.

### 2. 개발 방향을 사전에 정밀하게 조율해두자

- 대략적인 방향성만을 정해두고 개발하는 것으로는 부족할 수 있겠다는 생각이 들었다.
- 기존에 작성된 코드를 최대한 참고하면서 형식을 일관성있게 맞추도록 노력하자.
- 관점 차이로 인해 구현 방식이 달라질 수 있는 부분은, 시작 전에 구체적인 예시와 샘플 코드를 공유하며 의견을 맞추자.

## **ReflectionTestUtils**

**정의**

- Spring Framework에서 제공하는 테스트 지원 유틸리티 클래스
- `org.springframework.test.util.ReflectionTestUtils`에 위치
- Java 리플렉션(Reflection)을 이용해 private/protected 필드, 메서드, 상속된 필드 등에 접근하거나 값을 설정할 수 있도록 도와줌
- 주로 단위 테스트에서 접근 제어자를 무시하고 내부 상태를 검증·조작할 때 사용

**주요 기능**

1. **필드 값 설정**
    
    ```java
    ReflectionTestUtils.setField(targetObject, "fieldName", value);
    ```
    
    - 접근 제한자와 무관하게 해당 필드에 값을 설정
    - 상속받은 필드도 접근 가능
2. **필드 값 조회**
    
    ```java
    Object value = ReflectionTestUtils.getField(targetObject, "fieldName");
    ```
    
    - private/protected 필드 값을 가져옴
3. **메서드 호출**
    
    ```java
    ReflectionTestUtils.invokeMethod(targetObject, "methodName", args...);
    ```
    
    - 접근 제한자에 관계없이 메서드를 호출
4. **상위 클래스 필드 접근**
    
    ```java
    ReflectionTestUtils.setField(targetObject, "fieldName", value, Class.class);
    ```
    
    - 특정 상위 클래스에 정의된 필드에 접근할 때 사용

**사용 예시**

```java
class UserService {
    private String secret = "hidden";

    private String getSecretMessage() {
        return "Secret: " + secret;
    }
}

@Test
void testPrivateAccess() {
    UserService service = new UserService();

    // 필드 값 변경
    ReflectionTestUtils.setField(service, "secret", "changed");

    // private 메서드 호출
    String result = ReflectionTestUtils.invokeMethod(service, "getSecretMessage");

    assertEquals("Secret: changed", result);
}
```

**장점**

- 테스트에서 접근 불가능한 필드·메서드에 손쉽게 접근 가능
- Mocking이 어려운 경우 내부 상태를 직접 설정 가능

**주의점**

- 프로덕션 코드에는 사용하지 않음 → 캡슐화를 깨뜨리기 때문
- 리팩토링 시 필드명·메서드명이 변경되면 테스트가 쉽게 깨질 수 있음
