## 작업 과정에서 배운 것

### 1. 중복되는 자료는 불필요하게 만들지 말자

ERD 설계와 Entity 클래스 생성을 마무리하고 나서, 도메인 정의에 대해 문서로 정리두어야겠다는 생각이 들었다.

엔티티별 필드 정보까지 세세하게 기록해두는 것이 좋을지가 고민이었다. 처음에는 최대한 작성해볼까 하는 생각이었으나, 도메인 정의에서 수정사항이 앞으로도 계속 발생할 수 있겠다는 생각이 들었다.

ERD를 통해 엔티티별 필드 정보를 확인할 수 있는데, 거의 비슷한 내용을 굳이 여러 곳이 정리할 필요가 있을까 하는 의문이 들었다. 괜히 관리해야할 것들만 늘어나고, 일관성을 유지하기는 더 힘들 것 같았다.

중복 요소를 줄여야 하는 것은 코드 뿐만이 아니다. 문서화 작업에서도 중복된 내용을 최대한 제거하고, 수정사항에 대해 대비를 해야겠다고 생각했다.

<br>

## 어려웠던 점

### 1. 공통으로 사용할 클래스 만들기

각 도메인 별 구체적인 개발을 하기에 앞서, 여러 도메인에서 공통적으로 사용할 클래스들을 먼저 구현하기로 했다. 설계를 하면서 고려해야 할 점이 많아서 힘들었다.

아직 도메인별 구체적인 작업에는 들어가지 않았기 때문에, 공통적으로 필요한 기능을 파악하고, 추후의 확장성까지 고려하는 것이 어려웠다.

예를 들면, 공통 Response 형태를 정의하기 위해 `Response<T>` 와 `ErrorResponse<T>` 클래스를 구현하여, 모든 컨트롤러가 일관된 구조로 응답을 반환하도록 만들었다. API 별로 제공해야 하는 정보가 모두 다르기 때문에, 모든 API에서 유연하게 사용될 수 있는 형태를 만들기 위해 고민했다.

개발 초기에 공통 요소를 잘 만들어두는 것이 프로젝트 전체의 향방에 큰 영향을 준다는 것을 다시 한 번 느낄 수 있었다.

# 2. 회고

## Keep

### **1. 이동 중에 궁금한 내용을 공부하는 습관**

- 지하철을 타다보면, 딱히 쉬기도 힘들고 그렇다고 무언가 집중이 필요한 작업을 하기도 어렵다. 그냥 가만히 서서 시간을 허비하게 되는 것 같았다.
- 요즘은 오고가는 시간에 그날 활동하면서 처음 들어봤거나 궁금해진 키워드들을 찾아보고 있다.
- 짧은 시간이어도 검색을 하거나, AI에게 검색을 하면서 궁금했던 부분을 이해하고, 의도하지 않았던 새로운 개념들도 접할 수 있었다. 개념에 대한 이해도가 쌓이니까 수업이나 프로젝트를 할 때도 더 많은 것을 배울 수 있었던 것 같다.
- 앞으로도 그날 궁금했던 것을 잘 기록해두었다가, 이동하는 시간을 통해 채워나가는 습관을 들이고 싶다.

<br>

## Problem

### 1. 개선 사항이 계속 나온다

- 설계를 마무리한 줄 알았는데, 실제 구현을 진행하면서 예상하지 못한 수정 사항이 자꾸 발생했다.
- 구현 중에 필요한 필드가 떠오르기도 했고, 더 효율적으로 처리할 수 있는 구조가 떠오르기도 했다.
- 처음부터 완벽한 설계를 하려고 하다보면, 실제 작업에 들어가는 시점은 점점 늦춰지게 된다.
- 또한 실제 작업에 들어가고 나서야 눈에 보이는 영역도 많다.

<br>

## Try

### 1. 너무 완벽한 계획을 세우려고 하지 말자

- 계획을 어느 정도 충분한 수준까지 수립했다면, 그것을 더욱 완벽하게 만들기보다는, 작업에 빠르게 착수해보는 것이 더 나을 수 있다.
- 작업 중에 얻게 되는 인사이트를 바탕으로 실행 중에 점진적으로 다듬는 방식이 더 효율적이다.
- 계획에서 미흡한 부분이나 개선할 부분은 언제든 발생할 수 있다. 일단 시작하고 빠르게 피드백을 받아 수정하는 방향으로 바꿔보자.

# 3. 학습내용

## @Convert 어노테이션

- JPA에서 사용하는 어노테이션
- 엔티티 필드와 데이터베이스 컬럼 사이의 값 변환 로직을 지정할 때 사용
- `AttributeConverter<X, Y>` 인터페이스를 구현한 클래스가 필요함

### 사용 예시

### 1. Enum을 문자열로 저장하기

```java
public enum Gender {
    MALE, FEMALE
}
```

```java
@Converter(autoApply = true) // 모든 Gender 필드에 자동 적용 가능
public class GenderConverter implements AttributeConverter<Gender, String> {

    @Override
    public String convertToDatabaseColumn(Gender attribute) {
        return attribute != null ? attribute.name().toLowerCase() : null;
    }

    @Override
    public Gender convertToEntityAttribute(String dbData) {
        return dbData != null ? Gender.valueOf(dbData.toUpperCase()) : null;
    }
}
```

```java
@Entity
public class User {

    @Convert(converter = GenderConverter.class)
    private Gender gender;

    // ...
}
```

### 2. JSON 문자열로 저장되는 객체 필드

```java
public class Address {
    private String city;
    private String street;
}
```

```java
@Converter
public class AddressConverter implements AttributeConverter<Address, String> {

    private final ObjectMapper objectMapper = new ObjectMapper();

    @Override
    public String convertToDatabaseColumn(Address attribute) {
        try {
            return objectMapper.writeValueAsString(attribute);
        } catch (JsonProcessingException e) {
            throw new RuntimeException(e);
        }
    }

    @Override
    public Address convertToEntityAttribute(String dbData) {
        try {
            return objectMapper.readValue(dbData, Address.class);
        } catch (IOException e) {
            throw new RuntimeException(e);
        }
    }
}
```

```java
@Entity
public class Customer {

    @Convert(converter = AddressConverter.class)
    private Address address;

    // ...
}
```

### `autoApply` 옵션

- `@Converter(autoApply = true)`로 지정하면,
    
    해당 타입을 사용하는 모든 필드에 `@Convert`를 생략해도 자동으로 적용됨
    
- 단, `@Convert`로 명시된 필드에는 자동 적용되지 않음

<br>

## ObjectMapper

- Java 객체를 JSON으로 변환(직렬화) 하거나, **JSON을 Java 객체로 변환(역직렬화)** 할 수 있도록 도와주는 Jackson의 유틸 클래스

### 주요 기능

| 기능 | 설명 |
| --- | --- |
| `writeValueAsString(obj)` | Java 객체 → JSON 문자열로 변환 |
| `writeValue(file, obj)` | Java 객체 → JSON 파일로 저장 |
| `readValue(json, Class<T>)` | JSON 문자열 → Java 객체로 변환 |
| `configure(...)` | 직렬화/역직렬화 동작 방식 설정 (null 처리, 날짜 포맷 등) |

### 예시 코드

### 1. Java 객체 → JSON 문자열 (직렬화)

```java
ObjectMapper mapper = new ObjectMapper();

User user = new User("Alice", 30);
String json = mapper.writeValueAsString(user);

// 결과: {"name":"Alice","age":30}
```

### 2. JSON 문자열 → Java 객체 (역직렬화)

```java
String json = "{\"name\":\"Alice\",\"age\":30}";
User user = mapper.readValue(json, User.class);

// user.getName() → "Alice"
```

### 자주 사용하는 설정

```java
ObjectMapper mapper = new ObjectMapper();

// 예쁘게 출력
mapper.enable(SerializationFeature.INDENT_OUTPUT);

// null 필드 제외
mapper.setSerializationInclusion(JsonInclude.Include.NON_NULL);

// 날짜 포맷 지정
mapper.setDateFormat(new SimpleDateFormat("yyyy-MM-dd"));

// 알 수 없는 필드 무시
mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);
```

### 파일/스트림 지원

ObjectMapper는 문자열뿐 아니라 다양한 **입출력 소스**도 지원함

```java
// JSON 파일 → 객체
User user = mapper.readValue(new File("user.json"), User.class);

// 객체 → JSON 파일
mapper.writeValue(new File("output.json"), user);
```
