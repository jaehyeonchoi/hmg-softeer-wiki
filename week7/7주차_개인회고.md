7주차가 끝났다. 이번 주까지는 개발이 일단락되어야 했기 때문에 정말로 바쁜 한 주였다.

<br>

기본적인 API 구현이 모두 끝났지만, 프론트엔드와의 연결이라는 더욱 큰 작업이 남아 있었다.

API 개발 과정에서 프론트엔드 팀원들과 지속적으로 소통하면서 조율을 했음에도 불구하고, 본격적인 연결 작업에 들어가자 여러 가지 문제들이 드러났다. 구현했어야 했지만 미처 챙기지 못한 API도 있었고, 이미 구현된 API 중에서도 프론트엔드에서 사용하려고 하니 응답 형태가 부족하거나, 프론트엔드에서 요청 시점에 가지고 있기 어려운 데이터를 포함해야 하는 경우도 있었다. API를 이미 일차적으로 완성해둔 상태였기 때문에 수정하려면 관련된 코드들에 영향을 줘서 어려움이 있었다. 계획 단계에서 모든 걸 완벽히 준비하기는 힘들고, 실제로 해보면서 알게 되는 부분도 있지만, 이런 문제들을 줄일 수 있다면 좋겠다는 생각이 들었다. 이번에 배운 점들을 다음 프로젝트에서는 좀 더 신경 써보고 싶다.

<br>

SSE를 활용한 실시간 통신 기능을 모두 구현해둔 상태였는데, 기능이 조금씩 확장되고 서비스의 요구사항도 변경되면서 처음 SSE 방식을 선택했던 논리가 점점 빈약해졌다.

처음에는 도우미 → 서버 → 고객의 단방향 통신 구조였고, 위치 갱신 주기도 길어서 업링크는 HTTP 요청으로, 다운링크는 SSE로 처리하기로 했었다.

하지만 프론트엔드 작업에 여유가 생기면서 환자 대시보드를 다시 만들기로 했고, 내부적으로 위치 갱신 주기가 너무 길다는 피드백도 나왔다. 이제는 양방향 통신 구조에 GPS 값이 변할 때마다 실시간으로 위치를 갱신해야 하는 상황이라, 더 이상 SSE를 사용할 이유가 없어졌다고 판단했다.

요구사항만 놓고 보면 웹소켓으로 전환하는 것이 타당해 보였다. 다만, 늦어도 다음 주 월요일까지는 기능이 완성돼야 하는 상황에서, 이미 구현해둔 실시간 통신 기능을 전면 수정해야 한다는 점이 큰 고민거리였다.

결국 수요일에 팀원들과 Dangle님과 상의한 끝에 웹소켓 방식으로 전환하기로 결정했다. 스스로도 납득하지 못하는 방식을 억지로 유지한 채 발표를 준비하는 건 맞지 않다고 판단했다. 목요일부터 일요일까지 4일 동안 속도를 내면 기능 구현은 충분히 가능할 것 같았다. 발표를 위한 챌린지 주제도 생각해야 했지만, 그보다 먼저 기본 기능은 최대한 타당성 있는 기술을 적용하여 만들고 싶었다.

다행히도 기본적인 통신 구조 자체는 SSE 방식으로 구현할 때 이미 만들어두었기 때문에 생각보다 재사용할 수 있는 부분이 있었다. 웹소켓을 처음 사용해보기는 하지만 참고할 자료가 많았기 때문에 주중에 기초적인 구현은 마무리할 수 있었다.

<br>

금요일에는 마지막으로 데모 활동과 스쿼드 세션을 진행했다. 모든 팀들이 대부분의 기능을 완성한 상태이기 때문에, 어떤 서비스인지 이전보다 훨씬 제대로 엿볼 수 있었다. 

우리 팀도 서비스를 시연하며 피드백을 받고 있었는데, 그 와중에 서버 에러가 발생해서 시연을 이어갈 수 없게 되었다. 처음엔 내부 로직 문제인 줄 알고 코드를 점검했지만, 알고보니 원인은 DB 커넥션 문제였다. 지금까지 생성된 DB 커넥션들이 적절히 정리되지 않아서 커넥션 풀이 꽉 차버렸고, 그 결과 DB 연결이 실패한 것이었다. 데모 전에 QA 활동을 여러 차례 했지만, 그때는 드러나지 않았던 문제였다. 많은 사람들이 모여있는 데모 도중에 이런 일이 발생한 건 당황스러웠지만, 차라리 지금 터진 게 다행이라는 생각도 들었다. 만약 다음 주 부스 시연 도중에 이런 문제가 생겼다면 훨씬 더 큰일이었을 것이다.

한편으로는, 이렇게 우리가 예상하지 못한 영역에서 서버에 문제가 생길 수 있다는 게 정말 무서웠다. 지금까지 문제가 없었다고 해서 앞으로도 문제 없을 거라고 단정할 수는 없다는 사실을 뼈저리게 느꼈다.

<br>

데모 활동이 끝난 후에는 스쿼드 세션을 진행했다.

프로젝트 진행 상황에 대해 서로 이야기를 나누다 보니, 대부분 챌린지 주제에 대해 고민 중이라는 걸 알 수 있었다. 나 역시 발표 주제를 확정하지 못해서 부담이 있었는데, 같은 고민을 하는 사람들이 생각보다 많다는 점에서 위안이 되었고, 실질적으로 도움이 되는 조언도 많이 주고받을 수 있었다.

지금까지 작업한 내용들과 고민 중인 주제를 공유했더니, 다른 사람들도 자신의 생각이나 피드백을 많이 이야기해줬다. 내가 구현한 방식 중 이상한 점들을 솔직하게 지적해주기도 했고, 새로운 아이디어들도 많이 제안해줬다. 덕분에 챌린지 주제 선정에 대한 인사이트를 많이 얻을 수 있었다.

그동안은 발표 주제에 대해서 팀원들하고만 이야기를 많이 했다. 우리 프로젝트에 대해서 가장 잘 알고 있는 사람들이기 때문이다. 하지만 오히려 너무 가까이서 보는 사람들이기 때문에 놓치는 부분들도 있는 것 같다. 이렇게 외부의 시각에서 본 피드백이 도움이 되는 부분도 많다는 걸 이번에 느꼈다.

<br>

개발 기간이 정말 얼마 남지 않았다. 해야 할 일도 많고 체력적으로도 지칠 때가 많지만, 지금이 아니면 더 하고 싶어도 할 수 없는 작업들이다. 남은 시간 동안 서비스의 완성도에 집중하면서, 도전해보고 싶은 영역에도 후회 없이 도전해보고 싶다.
